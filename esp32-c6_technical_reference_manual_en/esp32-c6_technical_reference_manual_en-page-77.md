The address and size of a region are specified by writing to maddress (tdata2) CSR for the selected trigger unit. Larger than 1 byte region sizes are specified through NAPOT (naturally aligned power-of-two) encoding (see Table 1.11-1) and enabled by setting match bit in mcontrol. Note that for NAPOT encoded addresses, by definition, the start address is constrained to be aligned to (i.e. an integer multiple of) the region size.\n\nTable 1.11-1. It is used for preventing triggers from causing repeated exceptions in machine-mode while execution is happening inside a trap handler. This CSR is not relevant if a trigger is configured to enter debug mode.\n\n1.11.3 Trigger Execution Flow\nWhen hart is halted and enters debug mode due to the firing of a trigger (action = 1):\n*   dpc is set to current PC (in decode stage)\n*   cause field in dcscr is set to 2, which means halt due to trigger\n*   hit bit is set to 1, corresponding to the trigger(s) which fired\nWhen hart goes into trap due to the firing of a trigger (action = 0):\n*   mepc is set to current PC (in decode stage)\n*   mcause is set to 3, which means breakpoint exception\n*   mpte is set to the value in mte right before trap\n*   mte is set to 0\n*   hit bit is set to 1, corresponding to the trigger(s) which fired\nNote: If two different triggers fire at the same time, one with action = O and another with action = 1, then hart is halted and enters debug mode.\n\n1.11.4 Register Summary\nBelow is a list of Trigger Module CSRs supported by the CPU.
